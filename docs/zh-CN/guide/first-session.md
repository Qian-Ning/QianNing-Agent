# 创建第一个项目会话

一次有效的首次体验应该证明四件事：模型服务能工作、会话绑定了正确项目、权限提示容易理解、任务结果可以验证。

## 连接一个模型

1. 打开**设置 → 模型**。
2. 添加或选择模型服务。
3. 填写该服务需要的接口地址与凭据。
4. 刷新服务模型目录，或选择一个模型。
5. 离开设置前运行连接测试。

QianNing Agent 支持内置服务配置、本地端点、自建网关和 OpenAI 兼容接口。接口形式、认证方式、模型目录、图片输入、推理等级、上下文大小和输出限制取决于具体服务。标注为 OpenAI 兼容，不代表它支持 OpenAI 的全部功能。

模型服务密钥不会进入 Renderer 或会话正文。界面只显示“已配置/未配置”，不会回显密钥。

## 创建第一个项目会话

1. 从侧边栏添加或打开项目。
2. 选择包含仓库或工作文件的目录。
3. 在这个项目下创建新会话。
4. 发送第一个任务前，再看一眼当前项目名。

持久会话保存自己的项目绑定。即使切换侧边栏正在显示的项目，后台会话的工具也不会被重定向。文件工具默认以该会话绑定的工作区解析相对路径；访问工作区之外的明确路径时，必须经过当前权限策略。

## 选择权限模式

第一次使用建议选择**询问**。需要确认的操作会由宿主显示权限卡；拒绝、超时或取消时，操作不会执行。

| 权限模式 | 实际用途 |
|---|---|
| **询问** | 执行前检查工具请求；学习应用时推荐使用 |
| **接受编辑** | 减少正常文件编辑的确认，同时保留其他敏感操作的提示 |
| **全自动** | 允许符合策略的操作不经确认运行；只有理解工作区与工具边界后再使用 |

会话工作模式与权限模式是两套控制。Agent、Plan、Goal 决定工作契约；询问、接受编辑、全自动决定宿主如何处理权限。

## 完成第一个可验证任务

第一项任务应当有明确结束条件，例如：

> 阅读这个项目，确认测试怎么运行；修复一个失败的单元测试，不改变公共行为；运行相关测试和类型检查；最后列出修改文件与实际命令。

可靠的结果应该在会话里留下这些证据：

1. 查看过哪些文件或符号；
2. 实际工具调用与输出；
3. 成功 Write 或 Edit 对应的可审查变更记录；
4. 测试或构建命令及退出结果；
5. 最终回答明确写出剩余阻塞，而不是含糊宣布成功。

可以在工作面板检查文件改动与可用的回滚证据。如果工具完成后又手动改了同一个文件，当前哈希不再等于工具完成时的哈希，宿主会拒绝旧快照回滚，避免覆盖后来的改动。

## 任务变大时使用 Plan 或 Goal

希望先批准实施路线时，选择 **Plan**。Agent 可以检查项目，随后提交不可变的 `.pi/plan/*.md` 文件；批准后才启动新的执行回合。

希望批准结果与边界、把实现选择交给 Agent 时，选择 **Goal**。契约会把目标和客观验收标准写入 `.pi/goal/*.md`。

宿主重启会中断待批准、排队或运行中的契约任务，不会自动重放。

## 让子智能体处理边界清楚的工作

QianNing Agent 内置探索、审查、测试、修复和 UI 设计子智能体。父 Agent 会判断某个独立且范围明确的任务是否值得委派。子智能体在后台运行，父任务可以继续推进；报告完成后会回到父任务，在最终交付前统一处理。

委派适合获取互不依赖的证据，不适合让多个 Agent 同时修改同一个文件。会话卡片和输入框上方运行面板会显示子智能体、模型、状态、耗时与最近工具动作。

## 停止、恢复与重启

- 停止会中断当前回合，并关闭活跃命令的完整进程树。
- 已完成的会话消息保存在 JSONL 文件中。
- 流式回复会定期保存检查点，崩溃通常只会损失最近一个保存间隔。
- 重启后，会话恢复项目绑定和已保存正文。
- 临时文件属于会话 scratch；删除会话时一并移除，启动时也会清理过期孤儿目录。
