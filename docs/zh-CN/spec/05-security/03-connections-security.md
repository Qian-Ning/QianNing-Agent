# 连接 安全规格

- 状态：目标规格；尚未实现
- 决策：D660 / ADR 0320，由 D661、D662 扩展
- 适用于：`connection.*` 方法域、`Connection` 与 `Console` 两个工具，以及它们
  作用的配置记录
- 不削弱：本地 MCP 边界（ADR 0203）、远端智能体控制边界（ADR 0205）、插件沙箱、
  供应商密钥边界
- 英文源规格：[英文源规格](/spec/05-security/03-connections-security)

## 1. 安全目标

该能力必须提供：

1. 一个无法自行扩大触达范围的主体 —— 智能体可以使用人启用了的目标，不能创建、
   编辑、启用或删除目标；
2. 凭据封闭 —— 口令或密钥材料永不进入模型上下文、工具结果、日志行或审计行；
3. 主机密钥完整性 —— 未知密钥是指纹化的拒绝，变更密钥永不被任何方法调用接受；
4. 不新增入向面 —— host-core 不绑定端口，本能力也不新增；
5. 有界资源使用 —— 每个操作都有超时、输出预算，以及随发起它的轮次一同终止的
   进程树；
6. 一条同时记录拒绝与执行的审计轨迹；
7. 安全默认 —— 在开关打开之前是关闭的，逐目标如此，全局也是如此。

本设计假定智能体可能被提示注入。提示、工具结果、目标上的文件、模型输出都是
不可信数据，**不得**授予已认证主体本来没有的权限。尤其是来自目标的文本是数据，
永远不是指令，也永远不是去触及第二个目标的理由。

## 2. 信任域与数据流

```text
┌──────────────────────────┐
│ 渲染层                    │  只有用户意图；无秘密、无 SQLite
│  连接 目的地               │
└───────────┬──────────────┘
            │ 既有 IPC 面
┌───────────▼──────────────┐
│ Electron Main            │  薄编排层；自己没有 SSH 子系统
└───────────┬──────────────┘
            │ stdio NDJSON JSON-RPC（既有）
┌───────────▼──────────────┐      spawn       ┌────────────────────────┐
│ Rust host-core           │ ───────────────▶ │ 系统 ssh / scp / sftp  │
│  connection/             │                  │ （子进程）             │
│  配置存储 + 策略          │                  └───────────┬────────────┘
│  秘密库（既有）           │                              │
└──────────────────────────┘                              ▼
                                              ┌────────────────────────┐
                                              │ 归用户所有的目标        │
                                              │ 远端 shell、设备        │
                                              └────────────────────────┘
```

| 域 | 信任假设 | 必须有边界 |
|---|---|---|
| 渲染层 | 对秘密不可信；可以显示配置，但永不显示凭据 | 既有类型化 IPC 面；不直连存储或进程 |
| Electron Main | 可信的编排者，不是凭据权威 | 转发调用；本条路径上不自行存放目标秘密 |
| Rust host-core | 本能力的策略与秘密权威 | 配置校验、设闸判定、审计、进程回收 |
| spawn 的 `ssh` 子进程 | 可信二进制的不可信执行代理 | 只经 argv；口令走 askpass 助手，永不走 argv |
| 目标 | 按敌意假定 | 输出是数据；不转发任何凭据；从它出发触及不到第二个目标 |
| 秘密库 | 秘密在静态时唯一所在之处 | 经既有机制加密落盘 |

## 3. 这不改变什么

这项能力常被描述成「让智能体进入其他机器」，这会把人引向错误的结论。准确地说：

- `Bash` 工具本来就能在本机执行 `ssh host '…'`。本能力没有让某个**新的类别**的
  机器变得可达；它给一条已经存在的路径加上了具名记录、策略与审计轨迹。
- 不引入新的权限。两个工具都是 `Risk::High`，沿用既有的 Plan 与 Goal 规则。
- 不新增网络监听者。host-core 仍然什么都不绑定，端口转发的监听者是子进程而不是
  宿主的。
- 不新增渲染层能力。渲染层仍然碰不到 SQLite，仍然不能 spawn 进程。
- 不复制凭据。桌面为 `pi-host` 引导已经在存放 SSH 材料的地方，§6 给出收敛规则，
  而不是再造一套存储。

## 4. 威胁与要求的行为

### 4.1 被注入的智能体去触及目标

**威胁。** 被投毒的工具结果、目标上的文件，或供应商响应，指示智能体去另一台主机
执行命令。

**要求。** 设闸判定（§5）按调用、针对智能体无法写入的宿主状态求值。用户没有启用
的目标按名字被拒绝。关闭的全局开关拒绝一切。智能体没有任何能创建或启用配置的
方法，因此它无法把一个目标提升为可达。

### 4.2 凭据泄露

**威胁。** 口令、私钥或口令短语经由结果、错误细节或日志行进入模型上下文。

**要求。** 见 §6。

### 4.3 主机密钥替换

**威胁。** 中间人出示自己的密钥，或一台曾被信任的主机出示了变更后的密钥。

**要求。** 每次探测都返回出示的指纹以及它是否已知。`strict` 拒绝未知密钥。
**变更**的密钥在任何策略下都被拒绝，清除它是在目的地里的人工行为 —— 永远不是
方法调用、`exec` 或重试能自己解决的。`accept-new` 配置记录一次密钥，此后即
`strict`。

### 4.4 来自目标的敌意输出

**威胁。** 目标返回被精心构造的数据，看起来像指令、试图打开第二条连接，或耗尽
内存。

**要求。** 输出是数据。它被预算（§7）、以本地命令工具的同一条规则截断，并溢出到
文件而不是无上限缓冲。溢出的流报出空档，而不是静默丢字节。输出通路上没有任何
东西把一个字节解释成决策。

### 4.5 借连接外泄

**威胁。** 智能体把连接当作外泄通道 —— 上传一个用户并不打算离开本机的文件。

**要求。** `upload` 只在会话工作区与 scratch 目录之内解析本地路径，与本地 `Read`
工具对路径施加的是同一条规则。两处之外的路径被拒绝。审计行记录该次传输、方向与
字节数。上传被 `15-workspace-ignore-rules.md` 覆盖的路径之前，先查该忽略规则。

### 4.6 资源耗尽与残留进程

**威胁。** 一条挂住的远端命令，或一个永远接受输入的目标，活过了轮次并耗着这台
机器。

**要求。** 每个操作都带超时，被夹到配置限额与宿主上限之间，超时是拒绝而不是退出
码。轮次被中止时，spawn 出去的进程树走终止本地命令的同一条路径，且回收覆盖转发
可能创建出来的隧道子进程。流在下列时刻关闭：会话被销毁、配置被禁用、全局开关被
关掉、宿主关闭。

### 4.7 串口设备作为旁路

**威胁。** 串口驱动硬件，其效果是物理的、且无法从返回结果中观察到 —— 这是唯一
一种失败模式不在数据里的目标种类。

**要求。** 串口配置与其他一样默认关闭，带同一条审计轨迹，受同一个超时约束。
目的地的配置详情中说明「串口动作可能改变物理状态」，因此用户批准的那条记录就是
描述它能做什么的那条记录。端口所有权是独占的：已被占用的口是拒绝，而不是与另一
持有者竞争。

## 5. 设闸边界

```text
allowed(profileId) = settings.remoteControlEnabled && profile.enabled
```

该判定在三扇门读取，且三处是同一个函数：面向智能体的方法、`tools.list` 的列表、
`tools.execute` 的分发。实现它的是两个文件 —— 方法注册表与工具注册表 —— 并有
一个测试断言两者一致，因为 D659 那类缺陷恰恰就是列表门与执行门互相跑偏。

开关是宿主状态。智能体没有写入它的方法，智能体面上也不暴露任何名字类似设置写入
的方法。

配置改动是用户能力，不在开关之后，因为那正是人打开一个目标的方式。但它仍是一个
受特权保护的改动：受宿主的普通角色规则约束，并被审计。

## 6. 秘密处理

| 规则 | 说明 |
|---|---|
| 存放 | 凭据存在既有秘密库里，加密落盘，由配置持有的一个引用指向 |
| 返回 | 任何面向智能体的方法都不返回该引用或值；面向用户的界面只知道「已配置凭据」 |
| 送入子进程 | 走 askpass 助手，永不作 argv 元素，永不走环境变量 |
| 工具结果 | 永不包含，错误细节也一样，包括失败**正是**认证失败时 |
| 日志 | 永不记录；spawn 路径自身的输出有一道脱敏步骤，既有的引导路径已经如此 |
| 审计 | 永不写入；审计行只有配置 id、动作、结果与计数 |
| 显示 | 目的地显示「是否已配置凭据」及其种类，永不显示其值 |

认证失败返回 `1034 CONNECTION_AUTH_FAILED`，点名配置，不带任何关于凭据的内容。
调用者无法用错误面区分「口令错」与「密钥错」，超出传输层自己报告的范围，因此该
错误不能被用作探测已存秘密形状的预言机。

## 7. 边界值

| 资源 | 上限 | 施加位置 |
|---|---|---|
| 命令墙钟 | 配置限额，被宿主上限夹住 | 子进程 spawn 之前 |
| stdout | 前 N 字节，之后以标记截断 | 抽取，与本地同一条规则 |
| stderr | 后 N 字节，之后以标记截断 | 抽取，与本地同一条规则 |
| 溢出文件 | 每个被截断的流一个，在本地 scratch 目录 | 溢出时 |
| 流环形缓冲 | 配置 `streamBytes`，默认每流 64 KiB | 写入环形缓冲时 |
| 打开的流 | 每个会话每条配置一个 | `open` 时 |
| 传输（R2） | 配置大小上限，默认每文件 64 MiB | 传输开始之前 |

配置限额可以调低宿主上限，**永远不能调高**。生效上限是两者较小值；当它与宿主
默认值不同时结果会报出来，因此拿到少于默认值的调用者知道原因，而不会怀疑是静默
失败。

## 8. 安全默认

- 全局开关关闭。全新安装下该能力是关闭的。
- 新配置处于禁用状态。创建目标不等于让它可达。
- 新配置的 `hostKeyPolicy` 是 `strict`。
- 新配置的 `multiplex` 是 `per-call`，因此除非用户要求，不存在共享连接。
- 删除配置时在同一个操作里删除其秘密；没有孤儿秘密活过一次删除。
- 关闭全局开关会关闭每一条打开的流，并拒绝此后每一次面向智能体的调用，包括已经
  持有配置 id 的那次。

## 9. 失败行为

| 失败 | 要求的行为 |
|---|---|
| 全局开关关闭 | `1029`；不做传输工作，不尝试连接 |
| 配置被禁用 | `1031` 并点名该配置；不尝试连接 |
| 配置 id 不存在 | `1030`；与「被禁用的配置」可区分，因为补救办法不同 |
| 主机密钥未知 | `1033` 并带指纹；配置的 `lastProbe` 记录这次拒绝 |
| 主机密钥变更 | `1033` 且 `kind: "changed"`；清除它需要人在目的地里操作 |
| 认证被拒 | `1034`；结果、日志、审计行中都不含任何关于凭据的内容 |
| 目标不可达 | `1032` 并点名阶段；可重试 |
| 超时 | `1035`；返回错误之前先终止进程树 |
| 传输没有 `exec` | `1037`，在任何连接尝试之前判定 |
| 平台没有实现 | `1036`；报出来，而不是返回一个空的成功 |
| 秘密库不可用 | 该配置无法用于认证；以拒绝上报，**绝不**回退到未加密存储 |
| 轮次被中止 | spawn 的进程树随轮次终止；没有子进程活过它 |

## 10. 验证要求

评审者必须能够通过**执行**来核查的安全属性：

1. 开关关闭时，每个面向智能体的方法与每个工具都返回文档记录的码，且
   `tools.list` 略去两个工具 —— 在两种开关状态下于两扇门都断言。
2. 配置无法通过任何面向智能体的方法创建、编辑、启用或删除 —— 穷举枚举，不是
   抽样。
3. 任何面向智能体的结果、审计行或日志行都不含凭据，成功与认证失败两种情形都
   如此。
4. 探测返回指纹；`strict` 下未知密钥被拒绝；变更密钥在任何策略下被任何方法拒绝。
5. 被中止的轮次在进程树两侧都不留下 spawn 出来的 `ssh` 进程。
6. 被截断的输出产生与本地相同的标记，以及一个本地 `Read` 工具能打开的溢出文件。
7. 配置处于连接状态、以及转发活跃期间，host-core 都没有监听套接字。
8. 对工作区与 scratch 目录之外路径的 `upload` 被拒绝，与本地 `Read` 工具同一条
   规则。

这些属性的端到端场景编号记录在 `06-delivery/04-e2e-test-plan.md`。
