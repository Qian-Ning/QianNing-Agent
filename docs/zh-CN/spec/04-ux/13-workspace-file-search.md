# 工作区文件搜索

状态：**后端已实现，选择器界面尚未做**。`host-core` 已能回答
`workspace.searchFiles`（有界、带排序的遍历，见
`crates/host-core/src/workspace_search.rs`），但目前没有界面消费它。下面「必须成立的规则」
描述的是**共享发现**那一版设计，第一版后端刻意跳过了它。

输入框有附件，agent 有 `search_files`，两者都不是工作区级的选择器。缺的是一个 **UI**，而填这个坑的成本不在排序，在并发。

## 本设计要避免的故障

文件选择器看起来像「列出工作区然后过滤」。天真实现会变成：每敲一个字就启动一次目录遍历，每次遍历都持锁，于是大仓库会把旁边同时打开的小仓库饿死。症状是第二个仓库打开时选择器卡住数秒 —— 而那恰好是用户最确信程序坏了的时候。

## 必须成立的规则

**1. 发现属于一次查询，不属于挂载。** 打开输入框或选择器不启动任何扫描。空查询用有界的目录前缀作答，而不是列出整棵树。

**2. 许可是分级的，不共享。** 发现、打分、空列表各取独立的小池子。一次大发现不能挡住小仓库的发现，也不能挡住空列表。获取许可可取消，并受查询截止时间约束。

**3. 查询挂到任务上，任务在最后一个消费者离开后短暂存活。** 同一根目录的每个查询都加入同一个发现任务并持有一份租约。关闭一个消费者只释放它自己的租约。最后一个离开后任务停留数秒，因为选择器每敲一个字就会中止上一个查询 —— 下一次按键必须重连，而不是重新走一遍。

**4. 取消的不能发布。** 被取消的 worker 绝不发布不完整快照；迟到的 worker 不能覆盖同根目录更新的任务。发布时在注册表锁内校验任务身份。

**5. 消费者代际拒绝过期回包。** 消费者已被替换后才到达的结果直接丢弃，不渲染。

**6. 处处有预算上限。** 缓存中的快照、跟踪的消费者、失败退避条目、协作截止时间都有上限。这里一张无界的 map 就是一个起名叫「缓存」的内存泄漏。

**7. 渲染层不做枚举。** 命令在原生侧排序并返回有界的一页。把整个工作区渲染出来再在浏览器里过滤，是同一个缺陷往上挪了一层。

## 对当前技术栈的含义

排序与遍历属于 `host-core`，和其余文件系统工作放在一起，不进渲染层，也不进 Electron main。渲染层只发起查询、消费有界结果；取消是调用的一等部分，不是等第一次「卡死」报告出现后才补上的东西。

忽略规则必须按根解析一次并共享：`.gitignore`、我们自己的忽略集、以及工作区边界都属于快照键的一部分，任一项变化即选择另一个快照，而不是原地修改一个。

## 明确不做

- 内容搜索（grep）。成本结构完全不同，且 agent 已有对应工具。
- 跨根统一排序。多根都会被搜到，但各自保留快照与预算。
- 跨启动的索引持久化。将来若加，磁盘索引需要同样遵守本页描述的任务身份纪律。
