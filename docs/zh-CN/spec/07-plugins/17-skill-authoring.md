# 17. 技能作者规范

> **翻译说明：** 本页是与 [英文源规格](/spec/07-plugins/17-skill-authoring) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

> 状态：与代码一致；下文每条上限与规则均取自运行中的代码，§10 列出各自由哪个文件强制。
> 范围：技能文档格式。市场目录条目元数据不在本页。

## 1. 范围

**技能**是一份 markdown 文档 —— 可选的 YAML frontmatter + 指令正文 —— 教 Agent 怎么做一件事。
它是用户**不写代码就能创作**的唯一扩展面。

本文规定**文档格式**：能放在哪、字段什么语义、有什么上限、宿主写回时保证什么、哪些规则有机检。
市场目录见 [/zh-CN/spec/07-plugins/07-plugin-marketplace](/zh-CN/spec/07-plugins/07-plugin-marketplace)；
扩展 API 见
[/zh-CN/spec/07-plugins/16-trusted-extensions](/zh-CN/spec/07-plugins/16-trusted-extensions)。

三个读取者，**故意不相同**：

| 读取者 | 职责 |
|---|---|
| **host-core**（`user_skills.rs`） | **权威**。发现、校验、写回。 |
| **桌面插件运行时** | 渲染模型看到的那条目录项，含截断。 |
| **技能导入器** | 扫描外部目录树，产候选 + 警告。 |

## 2. 文档可以放哪

| 根 | 形态 | id 来源 |
|---|---|---|
| 随构建内置的资源目录 | 每技能一个 `*.md`，直接放在该目录 | `qianning/<去掉扩展名的文件名>` |
| 用户技能与导入技能 | 松散的 `*.md`，或 `<技能名>/SKILL.md` | 文档的 `name`（§4.1） |

- **移动的单位是目录，不是文档** —— 技能可能在 `SKILL.md` 旁挂同级资源。
- **直接躺在技能目录里的松散 `SKILL.md` 不算目录形态**：它的父目录就是技能目录本身，
  当成技能目录会把**所有技能一起搬走**，所以按松散文档处理。

内置根**从文件名派生 id**（不从 frontmatter），因此不会出现"文件加了却没有登记项 ⇒ 静默失效"，
也不会"文件删了却留个指向空的登记项"。有 **3 个 id 被显式钉住** —— 它们早于文件名规则，
且**已经写进存过的转录**，改名会打断一个已经存在的引用。**被钉住的 id 是兼容承诺，不是偏好。**

## 3. 文档形态

```markdown
---
name: 简短技术名
description: 触发条件，不是摘要
---

markdown 正文。
```

frontmatter **可选**。没有它的文档仍是合法技能：显示名取自路径（§4.1），全部文本即正文。

宿主写回时**只写这一种形状**：

```
---\nname: <name>\n---\n\n<body>
```

## 4. frontmatter 字段

### 4.1 `name`

| 属性 | 值 |
|---|---|
| 是否必需 | **必需**。缺失或为空都报 `SKILL_INVALID: the file needs a name`。 |
| 上限 | **120 characters**（`MAX_NAME_CHARS`）。 |
| 超限时 | **被裁剪**，不是被拒绝。 |
| 回退 | 字段缺失但路径能给出时，取路径末段。 |
| 非 ASCII | **允许**。中文标题是常见情况。 |

显示名是 **id 的唯一来源**。id 由 name、路径、**64 字符**预算共同派生；派生不出合法 id 时，
依次回退到技能目录、再回退到哈希（`capability_id`）。**id 撞车时丢弃而不是改名** ——
两份文档自称同名，不会两个都加载。

### 4.2 `description`

| 属性 | 值 |
|---|---|
| 是否必需 | **否**（host-core 层面）。空的 description 不会让发现失败。 |
| 截断于 | **240 characters**（`MAX_SKILL_DESCRIPTION_CHARS`），末尾加 `…`。 |
| 由谁要求 | **导入器**会警告 `frontmatter missing description`。 |

把它写成**触发条件** —— 什么情形下该用这份技能 —— 而不是正文摘要。
它是模型用来判断"要不要加载这份文档"的文字；写成目录式摘要，就等于永远不会命中。

### 4.3 `version`

`version` 是**市场目录条目**（`SkillCatalogEntry`）的字段。**host-core 不消费它**：
文档安装后没有任何代码读它，它**不**把已装文档绑定到某个修订。
文档可以带它，改名时也会被原样带过，但**没有任何机制强制它的含义**。

**这是刻意为之，并且写在这里，就是为了不让任何人假设一个不存在的保证。**
要让已装技能收到变更，市场更新文档；要让用户钉住某个修订，那是目录的事，不是 frontmatter 的事。

### 4.4 未知键

宿主**渲染**文档时会**丢掉**未知顶层键。改名**不会**丢（§7），渲染会。
不要把任何承重信息放在本规范之外的键上 —— 一次经过渲染器的往返就会静默删掉它。

### 4.5 嵌套键

**缩进行不会被解析成字段。** 它们不进字段表，并被当作块标量（block scalar）的续行。
因此 `metadata:` 子树是**以文本形式**被带着走的，**任何读取者都无法以 `metadata.author` 取到它**。
凡是读取者必须看到的字段，都放在顶层、不要缩进。

## 5. 解析规则

解析器在**边缘故意宽松、在中间严格**。那些宽松情形存在的目的是**保护文档不被一次改写损坏**，
而不是因为它们是好风格。

| 输入 | 结果 |
|---|---|
| 开头字节序标记（BOM） | **先被剥掉**。 |
| 开头 `---`，其后本行只剩空白 | **接受**。`---`、`--- `、`---\r` 都能开块。 |
| 开头 `---x` | **不是** frontmatter，全部文本即正文。 |
| 块未终止 | **不是** frontmatter。文本成正文，宿主在其上方写一个**完整的新块**。 |
| 一行 trim 后只有 `---` | **终止符**。其后全部是正文。 |
| 块内空行 | 跳过。 |
| 以 `#` 开头的行 | 跳过。YAML 注释不是字段。 |
| 不含 `:` 的行 | 跳过。 |
| 缩进行 | 作为字段跳过；当作块标量内容。 |
| **重复键** | **最后一次出现胜出** —— 块被读进一个 map。 |

最后一条对作者有直接后果：**第二行 `name:` 会静默覆盖第一行。**
宿主的改名路径因此**丢弃**后面的出现而不是保留：留一个陈旧的值，会让文档**保留旧显示名，
而改名却声称已经改了**。

## 6. 上限

| 上限 | 值 | 常量 |
|---|---|---|
| 文档大小 | **128 KiB**（131,072 bytes） | `MAX_SKILL_BYTES` |
| `name` 长度 | **120 characters** | `MAX_NAME_CHARS` |
| `description` 长度 | **240 characters** | `MAX_SKILL_DESCRIPTION_CHARS` |
| id 长度 | **64 characters** | `capability_id(…, 64)` |
| id 形态 | `^[a-z0-9][a-z0-9-]{0,63}$` | `SKILL_ID` |

**大小上限是唯一会大声失败的**：超限文档被 host-core **拒绝**而不是截断 ——
截断一份指令文档，会静默删掉真正要紧的那部分。name 与 description 的上限是外观性的，**裁剪**即可。

## 7. 写回时保留什么

这是宿主碰用户手写文档时**最要紧的保证**，而且它比看起来更窄：

- **改名只重写 `name` 行。** 其余每一行 —— 额外字段、空白、行尾、正文 —— **逐字节**复制通过。
  必须改显示名的移动**不允许重排版文档**：渲染会归一化散文、丢掉未知键、重排正文缩进，
  等于**静默编辑一个用户只要求挪个位置的文件**。
- **已有 frontmatter 时**：新 `name:` 行写在**第一行 `name:` 的位置**；原本没有则写在终止符之前。
  后面的 `name:` 行被丢弃（§5）。
- **没有可用 frontmatter 时**（缺失，或开头未终止）：在文本上方写一个**完整的新块**。
- **渲染不是改名。** 只有渲染才丢未知键、才归一化空白。想要保留的调用方必须走改名路径。

## 8. 本仓库的必需约定

这些是项目政策而非格式规则，且有门强制（§10）：

- **每份内置技能文档都必须带 `## Origin` 段落**，首行为 `QianNing Agent`；且不得出现上游产品名。
- **`name` 是简短技术名** —— 模型要读它，短名字省上下文。品牌由 **id** 承载；
  id 兼作斜杠命令名，是**用户可见面**。
- **`description` 是触发条件**，并受 §4.2 上限约束。
- **正文以自己的指令收尾**，不用一句"本文介绍了……"来结束。

## 9. 改动已有文档

- **改 `name` 就改了派生出的 id**（除非 id 被钉住，见 §2）。已装技能的 id 可能因此改变，
  旧 id 不再解析。**已经存在引用时，把 id 钉住。**
- **不要为了整齐而重排 frontmatter。** 字段顺序无语义，重排只会造出一个**掩盖了真正改动的 diff**。
- **改 description 就是改行为。** 它是模型匹配的依据 ⇒ 它决定哪些任务会加载这份文档。
  按"变更"来审，而不是当文案润色。
- **正文保持为一份文档。** 一份链接到五份碎片的技能，其碎片会在**失去上下文**的情况下被加载 ——
  而 Agent 会读它被指向的东西。

## 10. 强制方式

下表每条规则都由右侧文件机检。**不在表里的规则是"人在遵守的约定"，不是保证。**

| 规则 | 由谁强制 |
|---|---|
| Origin 段落存在、无上游产品名（§8） | `scripts/check-skill-provenance.mjs`，由 `.github/workflows/skills-check.yml` 运行 |
| 上限与本文一致（§6） | `scripts/check-skill-authoring-spec.mjs`，同一工作流，**独立 job** |
| 两种语言的规范都存在 | 同上 |
| `SkillCreate` 宣告的上限与 §6 一致，且正文上限用**被强制的那种单位** | `apps/desktop/test/skill-authoring-tool.test.mjs` |
| 发现能覆盖每一份内置文档 | `apps/desktop/test/builtin-skill-discovery.test.mjs` |
| name 必需、裁剪、id 派生、改名保留 | `crates/host-core/src/user_skills/tests.rs`、`agent_capabilities/tests.rs` |
| 导入器对缺字段的警告 | `apps/desktop/electron/test/agent-skill-scan.test.mjs` |

## 11. 作者自检清单

- `name` 在顶层、未缩进、且不超过 **120 characters**？
- `description` 是**触发条件**，而不是摘要？
- `name` 够短吗 —— 模型每一轮都在为它付上下文费？
- id 才是身份；**已有引用时钉住了吗**？
- 读取者需要的字段都在顶层，而不是缩在某个子树下？
- 有没有**两行 `name:`**（只会读到最后一行）？
- 文档是否在 **128 KiB** 以内？超了之后它还可读吗？
- 正文是否**以指令收尾**，而不是以"描述自身"收尾？
- 有 `## Origin` 段落吗？文档里出现上游产品名了吗？
- 把这份文档**单独**读、旁边不放任何同级文件，它还成立吗？
